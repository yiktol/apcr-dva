# Real React SPA served by the coffee-ship container

The coffee-ship container now serves a baked React (Vite) SPA alongside its existing JSON API, so the CloudFront → ALB → ECS/Fargate path renders an actual Coffee Ship storefront instead of a JSON blob. The stdlib-only Python server (`app.py`) gained static-file serving from `/app/static`; a multi-stage Dockerfile builds the SPA in a node stage and bakes `dist` + `architecture.svg` into the python runtime stage; `deploy.sh` and `buildspec.yml` were adjusted (packaging excludes + comments) with no behavioral change to the real pipeline. The JSON API is preserved byte-for-byte and `GET /` now returns HTML 200, keeping the ALB health check green.

Watch for: the `GET /` contract changed from JSON `{"status":"ok"}` to HTML — this is the task's explicit requirement and the health check still passes 200 (confirmed), so it is not a regression. No live AWS deploy occurred; all verification is local (confirmed via git log + FEAT evidence).

**Verdict**: APPROVED

## High-level view

The design keeps the architecture and the real pipeline untouched and solves the "page is still nginx / no web page" problem by baking the SPA into the same container that already serves the API, served same-origin. No infra edits, no new runtime dependencies — `app.py` stays stdlib-only (adds only `mimetypes`), `requirements.txt` stays empty, container name stays `web`.

The API surface is held to its contract: `GET|POST /order` and `compute_points` are unchanged (floor(total)×10), `GET /health` adds only a `version` field, and `GET /` returns `index.html` as HTML 200 so the ALB health check that targets `/` still passes. Static routing adds SPA fallback for client-side routes and a 404 for missing asset-looking paths, with path-traversal guarded by realpath confinement under `STATIC_DIR`.

The pipeline inputs are consistent: the multi-stage Dockerfile's COPY sources (`frontend/`, `architecture.svg`) all live inside the `container/` build context that both `deploy.sh` and `buildspec.yml` build; `buildspec.yml` keeps `py_compile` and `imagedefinitions.json` name `web` with no `|| true` gates; `deploy.sh` ships the SPA sources + svg but excludes local `node_modules/` and `dist/`. Region stays `ap-southeast-1`.

Verification is local-only and actually ran: SPA build succeeds, py_compile passes, and a runtime smoke test confirms every route contract. No AWS-mutating command was executed.

### JSON API preserved byte-for-byte

`compute_points` is unchanged from main: `int(float(total)) * POINTS_PER_DOLLAR`, same negative/missing-total ValueError → 400 mapping. `do_POST` on `/order` is identical. `GET /order` still returns the sample `{"orderId":"sample-order","points":...}`. The runtime smoke test confirmed `POST /order {"total":12.5}` → `{"orderId":"t1","points":120}` and `GET /order` → sample JSON 200 (confirmed). `GET /health` previously returned `{"status":"ok"}` and now returns `{"status":"ok","version":APP_VERSION}` — additive only, matching the "adds only version" contract (confirmed).

### GET / moved from JSON to HTML, health check preserved

On main, `/` and `/health` both returned `{"status":"ok"}`. Now `/` serves `index.html` as `text/html` 200, and `/health` is the sole JSON status route. The ALB target group health check targets `GET /` expecting 200 (per the pattern default confirmed in the plan against `app-pipeline-stack.ts`), and `/` still answers 200 — verified by curl returning `200 text/html`. `_serve_index` also falls back to a tiny placeholder HTML page if `dist` was never baked, so `/` is 200 even in a degraded image. This is a deliberate, task-required contract change, not a regression (confirmed).

### Static serving and path-traversal guard

Unknown paths route by shape: an existing file under `STATIC_DIR` is served with a `mimetypes`-guessed Content-Type; a missing asset-looking path (dot in the last segment, e.g. `/nope.js`) returns 404; any other unknown path falls back to `index.html` 200 for client-side routing. Traversal is blocked by resolving the candidate with `os.path.realpath` and requiring it to equal or sit under the resolved `STATIC_DIR` root. Smoke test confirmed `/nope.js` → 404, `/some/spa/route` → HTML 200, and `--path-as-is /../app.py` → 404 (confirmed). The server is same-origin and unauthenticated by design (the SPA POSTs relative `/order`); no new trust boundary or credential handling is introduced, consistent with the existing posture.

### Multi-stage Dockerfile and build context

Stage 1 (`node:20-alpine`) runs `npm ci` then `npm run build` → `/build/dist`; stage 2 (`python:3.12-slim`) copies `app.py`, `requirements.txt`, `--from=build /build/dist` → `/app/static`, and `architecture.svg` → `/app/static/architecture.svg`. All COPY sources (`frontend/`, `architecture.svg`) live inside the `container/` build context that `deploy.sh` and `buildspec.yml` both build (confirmed present). Runtime stage installs nothing via pip — `requirements.txt` stays an empty comment, so the image is stdlib-only. `ENV PORT=8080`, `EXPOSE 8080`, and `CMD ["python","app.py"]` are unchanged.

### Pipeline packaging unchanged in behavior

`buildspec.yml` keeps `python -m py_compile container/app.py` as a hard gate and emits `imagedefinitions.json` with name `web`; the only `|| true` token is a comment affirming no gates exist (confirmed by reading the file). The npm build runs inside the privileged CodeBuild docker build, so no new buildspec phase was added. `deploy.sh` adds `-x '*/node_modules/*' -x '*/dist/*'` to the source zip so a developer's local install/build output is not shipped; the zip dry-run confirmed `container/frontend/*` and `architecture.svg` are included while node_modules/dist are absent (confirmed). Region stays pinned to `ap-southeast-1`.
